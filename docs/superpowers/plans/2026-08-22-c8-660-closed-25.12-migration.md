# C8-660 Closed 25.12 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace every legacy closed build entry with one reproducible C8-660 ImmortalWrt 25.12 build using `mt_wifi` 7.6.7.3 and verified RM520N HNAT plus WARP/WED acceleration on the active data plane.

**Architecture:** A dedicated closed workflow consumes a pinned `chasey-dev/immortalwrt-mt798x-rebase:25.12` revision, injects a closed-specific C8 target into the upstream tree, and enforces the vendor-driver configuration before compiling. Repository tests validate source pinning, target injection, config and artifact contracts; router acceptance proves the default RM520N RGMII/IPPT `eth1` path through increasing PPE `BIND` entries. `rxppd` is required only for an explicitly selected external USB/QMI data plane.

**Tech Stack:** GitHub Actions YAML, OpenWrt/ImmortalWrt Kconfig and Make, POSIX shell, Linux 6.12 device tree, MediaTek `mt_wifi`/HNAT/WARP, fw4, netifd, ucode `hnat-detect`, QMI/uqmi.

**Spec:** `docs/superpowers/specs/2026-08-22-c8-660-closed-25.12-migration-design.md`

## Global Constraints

- Source repository is exactly `https://github.com/chasey-dev/immortalwrt-mt798x-rebase`, branch `25.12`, initially pinned to `2d0e93b1253660ae15d195786cd7fa913d70d42a`.
- Closed wireless is exactly `mt_wifi` 7.6.7.3; closed artifacts must not contain the mt76/mac80211 radio stack.
- HNAT acceptance includes the active RM520N WAN for both LAN and WiFi traffic; the default data plane is RGMII/IPPT on `eth1`, while USB/QMI external HNAT is conditional on selecting that data plane.
- WED evidence is the vendor `mt_wifi -> mtk_warp_proxy -> WARP/WED -> HNAT/PPE` chain, not mt76 `wed_enable=Y`.
- Delete the active 21.02 workflow and the retired 24.10 archive; do not create another legacy build entry.
- Preserve all pre-existing uncommitted Open-build, proxy, README, SMS, and `.omo` work; merge only the lines required by this migration.
- Do not commit, stage, push, publish a release, or dispatch an external workflow automatically from the dirty working tree.
- A build is not accepted until a real C8-660 shows PPE `BIND` growth for RM520N-to-LAN and RM520N-to-WiFi traffic and retains software-forwarding fallback.
